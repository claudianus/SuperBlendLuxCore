# 2026-10-19 — Viewport draw error Stop ownership

배포된 fix3의 view_draw 오류 처리에서 SessionWorker.submit_stop() 뒤 UI 스레드가 같은 session.Stop()을 직접 호출하는 결함을 확인했다. worker의 session_lock은 readback/OIDN/scene edit를 직렬화하지만 UI의 직접 Stop은 이를 우회했다. API_BEGIN/END는 logging만 수행하고 Stop/UpdateStats binding은 GIL을 해제한다. RenderEngine::Stop의 started 검사는 engineMutex 획득 앞에 있다. 따라서 native가 모든 진입을 자동 직렬화한다고 볼 수 없다. 테스터의 실제 Windows10 RTX5070Ti 크래시와 동일 원인은 아직 입증하지 않았다.

수정은 engine/base.py의 view_draw exception recovery 한 곳이다: worker가 있으면 queued worker Stop에만 맡기고, worker-less legacy 경로에서만 기존 직접 Stop을 유지한다. 정상 draw, 실패 세션/exporter 표시 정리와 원래 오류 메시지는 보존한다. UI에서 read/OIDN 완료를 join하지 않는다. Native renderer/helper/kernel/default/transport 코드는 바꾸지 않았다.

Production-body baseline은 readback/OIDN/edit/idle 네 변형에서 owner lock 우회를 기록했고 정상/legacy 세 control은 통과했다. 수정 후 frozen worker 및 현재 WIP worker로7/7 통과한다. 한 결함의 변형 수이며 독립 버그4건이 아니다. native 작업은 모형이고 실제 native GPU crash 재현은 아니다.
